# Unitree G1 Push Experiment

This note documents the real-robot push experiment pipeline for the 29-DoF Unitree G1.

The push experiment starts from a flat locomotion policy trained in Isaac Lab:

## 1. Train the Locomotion Policy

The push experiment uses the 29-DoF Unitree flat locomotion task:

```text
Isaac-Velocity-Flat-G1-29DOF-UNITREE-PPO
```

The training script expects the base task name above and appends `-POLICY` internally.
The actual Gym task registered by the repo is therefore:

```text
Isaac-Velocity-Flat-G1-29DOF-UNITREE-PPO-POLICY
```

Relevant source files:

```text
safety_value/scripts/0_policy/train.py
source/hj_humanoid/hj_humanoid/tasks/manager_based/hj_flat_push/config/g1/__init__.py
source/hj_humanoid/hj_humanoid/tasks/manager_based/hj_flat_push/config/g1/agents/rsl_rl_ppo_cfg.py
source/hj_humanoid/hj_humanoid/tasks/manager_based/hj_flat_push/config/g1/flat_env_cfg.py
```

### Environment Setup

Run from the repository root inside the Isaac Lab Python environment. The extension
and the `safety_value` package should be installed in editable mode:

```bash
python -m pip install -e source/hj_humanoid
python -m pip install -e safety_value
```

### Training Command

The command used for the hardware push policy is:

```bash
python safety_value/scripts/0_policy/train.py \
  --task Isaac-Velocity-Flat-G1-29DOF-UNITREE-PPO \
  --num_envs 8192 \
  --max_iterations 15000 \
  --seed 42 \
  --headless
```

### Output Layout

The runner config sets:

```text
experiment_name = g1_29dof_flat_unitree_ppo
```

Training outputs are written to:

```text
logs/rsl_rl/g1_29dof_flat_unitree_ppo/<timestamp>/
```

Each run contains:

```text
model_*.pt            RSL-RL policy checkpoints
params/env.yaml       resolved Isaac Lab environment config
params/agent.yaml     resolved RSL-RL PPO config
params/env.pkl
params/agent.pkl
```

Choose one policy checkpoint for deployment and keep it fixed for all downstream
steps. The same checkpoint must be used for safety-value data rollout, ONNX
export, sim-to-sim validation, and real-robot deployment.

```text
logs/rsl_rl/g1_29dof_flat_unitree_ppo/<POLICY_RUN>/model_<POLICY_STEP>.pt
```

### What This Policy Trains

The actor is deployable on the Unitree controller:

```text
actor observation: 480 dims
action:            29 dims
control rate:      50 Hz
```

The 480-dimensional actor observation is a 5-frame history of:

```text
base_ang_vel          3
projected_gravity     3
velocity_commands     3
joint_pos_rel        29
joint_vel_rel        29
last_action          29
```

That is `96` dims per frame, stacked for `5` frames. The critic is asymmetric and
adds privileged base linear velocity, but deployment uses only the actor observation.

The PPO actor and critic both use:

```text
hidden_dims = [512, 256, 128]
activation  = elu
init_std    = 1.0
```

The policy outputs a 29-DoF `JointPositionAction` over the explicit Unitree joint
ordering in `G1_29DOF_JOINT_NAMES`.

## 2. Train the Safety Value Function

The safety value function is trained in this repository as well. It is not trained
from real-robot logs. Instead, it is trained from Isaac Lab rollouts generated by
the exact locomotion policy checkpoint that will later be deployed.

Set `POLICY_RUN` to the timestamp directory under
`logs/rsl_rl/g1_29dof_flat_unitree_ppo/`, and set `POLICY_STEP` to the checkpoint
number in `model_<POLICY_STEP>.pt`.

The safety-value training pipeline is:

```text
fixed locomotion policy checkpoint
  -> rollout safety data in Isaac Lab
  -> process raw HDF5 into train/test datasets
  -> train lambda-reachability safety value
  -> produce a safety-value checkpoint
```

Relevant source files:

```text
safety_value/scripts/1_data_prep/rollout_safety_data.py
safety_value/scripts/1_data_prep/data_processing.py
safety_value/scripts/2_safety_analysis/train.py
safety_value/safety_analysis_algos/lambda_reachability/trainer.py
source/hj_humanoid/hj_humanoid/tasks/manager_based/hj_flat_push/config/g1/flat_env_cfg.py
```

### 2.1 Roll Out Safety Data

Use the fixed push policy checkpoint to collect simulated trajectories with safety
signals and push-event flags. The script appends `-SAFETY-ROLLOUT` internally, so
the base task name is still used on the command line.

```bash
POLICY_RUN=<your_policy_run>
POLICY_STEP=<your_policy_step>
POLICY_CKPT=logs/rsl_rl/g1_29dof_flat_unitree_ppo/${POLICY_RUN}/model_${POLICY_STEP}.pt
SA_ROOT=g1_29dof_flat_unitree_ppo_${POLICY_STEP}

python safety_value/scripts/1_data_prep/rollout_safety_data.py \
  --task Isaac-Velocity-Flat-G1-29DOF-UNITREE-PPO \
  --checkpoint ${POLICY_CKPT} \
  --safety_analysis_root ${SA_ROOT} \
  --num_envs 4096 \
  --video_length 1000 \
  --seed 42 \
  --headless
```

This writes:

```text
logs/safety_analysis/<SA_ROOT>/data_raw.hdf5
```

The raw dataset records `policy_obs`, the push safety signal, event flags, and
other rollout fields for each simulated episode. For the push task, the safety
signal is the balance signal used by the local recorder.

### 2.2 Process the Rollout Dataset

Convert the raw HDF5 rollout into the train/test datasets consumed by the safety
value trainers:

```bash
python safety_value/scripts/1_data_prep/data_processing.py \
  --safety_analysis_root logs/safety_analysis/${SA_ROOT} \
  --raw_dataset_name data_raw.hdf5 \
  --test_proportion 0.2
```

This writes:

```text
logs/safety_analysis/<SA_ROOT>/data_processed_train.pkl
logs/safety_analysis/<SA_ROOT>/data_processed_test.pkl
```

By default, the processing step segments trajectories at event flags. For the
push safety rollout, the event flag corresponds to the simulated push onset.

### 2.3 Train Lambda-Reachability

Train the deployed safety value model with lambda-reachability at `lambda=0.99`:

```bash
python safety_value/scripts/2_safety_analysis/train.py \
  --safety_analysis_root ${SA_ROOT} \
  --algo lambda_reachability \
  --model_tag lambda_reachability \
  --run_name lambda_reach_lambda_0_99 \
  --lambda_param 0.99 \
  --max_horizon 200 \
  --alpha_bce 5.0 \
  --weight_main 1.0 \
  --weight_hinge_lb 1.0 \
  --weight_hinge_mono 1.0 \
  --weight_bce 1.0 \
  --target_tau_lambda 0.005 \
  --target_update_period 1 \
  --total_steps 10000 \
  --eval_steps 500 \
  --eval_batches 0 \
  --batch 256 \
  --lr 1e-3 \
  --hidden_dims 256 256 \
  --seed 0 \
  --device cuda \
  --epochs 20
```

This writes the safety-value checkpoint used later for deployment:

```text
logs/safety_analysis/<SA_ROOT>/results/
  lambda_reachability_lambda_reach_lambda_0_99/
    training_config.json
    models/last_seed_0.pt
```

The trained value function takes the same 480-dimensional actor observation used
by the policy and outputs one scalar safety value. In deployment, lower values are
safer and positive values indicate predicted future unsafe behavior.


## 3. Export Models to ONNX

Both the locomotion policy and the safety value function must be exported to ONNX
before `unitree_rl_lab` can load them.

Assume the variables from step 2 are still set:

```bash
POLICY_RUN=<your_policy_run>
POLICY_STEP=<your_policy_step>
POLICY_CKPT=logs/rsl_rl/g1_29dof_flat_unitree_ppo/${POLICY_RUN}/model_${POLICY_STEP}.pt
SA_ROOT=g1_29dof_flat_unitree_ppo_${POLICY_STEP}
```

### 3.1 Export the Locomotion Policy

`play.py` exports `policy.onnx` alongside the checkpoint as a side effect of a
one-step headless run:

```bash
python safety_value/scripts/0_policy/play.py \
  --task Isaac-Velocity-Flat-G1-29DOF-UNITREE-PPO \
  --checkpoint ${POLICY_CKPT} \
  --num_envs 1 \
  --headless
```

The export is written to:

```text
logs/rsl_rl/g1_29dof_flat_unitree_ppo/<POLICY_RUN>/exported/policy.onnx
```

The ONNX actor takes a `[1, 480]` observation and produces a `[1, 29]` action.

### 3.2 Export the Safety Value Function

```bash
SV_RUN=lambda_reachability_lambda_reach_lambda_0_99
SV_DIR=logs/safety_analysis/${SA_ROOT}/results/${SV_RUN}

python deploy/tools/export_onnx.py \
  --safety_value_dir ${SV_DIR} \
  --output ${SV_DIR}/exported/safety_value.onnx
```

The script reads `training_config.json` from `${SV_DIR}`, resolves the latest
checkpoint in `${SV_DIR}/models/`, exports to ONNX, and verifies the graph.
The safety value ONNX takes a `[1, 480]` observation and outputs a `[1, 1]` scalar.

## 4. Deploy with unitree_rl_lab

Clone [unitree_rl_lab](https://github.com/intelligent-control-lab/unitree_rl_lab-lambda) and follow
its README to build the SDK and install dependencies. The commands below use
`UNITREE_RL_LAB` for its root; set it to wherever you cloned the repo:

```bash
UNITREE_RL_LAB=<path-to-unitree_rl_lab>
```

`unitree_rl_lab` loads policy and safety-value ONNX models from a *policy directory*
whose path is set in `${UNITREE_RL_LAB}/deploy/robots/g1_29dof/config/config.yaml`.

### 4.1 Create a Policy Directory

Choose a name for this deployment (e.g. `my_push_policy`) and set up the directory:

```bash
POLICY_NAME=my_push_policy
DEPLOY_DIR=${UNITREE_RL_LAB}/deploy/robots/g1_29dof/config/policy/velocity/${POLICY_NAME}

mkdir -p ${DEPLOY_DIR}/exported ${DEPLOY_DIR}/params

# copy the two ONNX models
cp logs/rsl_rl/g1_29dof_flat_unitree_ppo/${POLICY_RUN}/exported/policy.onnx \
   ${DEPLOY_DIR}/exported/policy.onnx
cp ${SV_DIR}/exported/safety_value.onnx \
   ${DEPLOY_DIR}/exported/safety_value.onnx
```

Create `${DEPLOY_DIR}/params/deploy.yaml` based on the reference push policy
(`unitree_flat_baseline_v4/params/deploy.yaml` in the repo) or write your own.
Key fields to set:

```text
step_dt: 0.02          # 50 Hz control rate
stiffness / damping    # match the flat_env_cfg.py actuator config
default_joint_pos      # match the flat_env_cfg.py default positions
actions.scale / offset # match the JointPositionAction config
observations.*         # match the actor observation order and scales
```

### 4.2 Point config.yaml at the New Policy

Edit `${UNITREE_RL_LAB}/deploy/robots/g1_29dof/config/config.yaml`,
set the `Velocity` FSM `policy_dir` and enable the safety-value monitor:

```yaml
  Velocity:
    policy_dir: config/policy/velocity/my_push_policy
    safety_value:
      enabled: true
      model_path: config/policy/velocity/my_push_policy/exported/safety_value.onnx
      log_dir: log/safety_value
      log_obs: true
      log_state: true
      safety_signal_type: tilt_only   # push task: balance signal
      max_queue_size: 10000
```

`safety_signal_type: tilt_only` matches the simulated push safety signal used
during safety-value training (see step 2).

### 4.3 Build the Controller

```bash
cd ${UNITREE_RL_LAB}/deploy/robots/g1_29dof
mkdir -p build && cd build
cmake .. && make -j$(nproc)
```

### 4.4 Sim-to-Sim Validation (MuJoCo)

Install and start [unitree_mujoco](https://github.com/intelligent-control-lab/unitree_mujoco-lambda).
The fork's `simulate/config.yaml` is pre-configured for G1 (`robot=g1`,
`domain_id=0`, `use_joystick=0`, `enable_elastic_band=1`).

```bash
# in unitree_mujoco/simulate/build
./unitree_mujoco
```

Then run the controller:

```bash
cd ${UNITREE_RL_LAB}/deploy/robots/g1_29dof/build
./g1_ctrl
# 1. Press [f]  →  FixStand
# 2. In the MuJoCo window press 8  →  feet touch ground
# 3. Press [v]  →  run policy (Velocity FSM)
# 4. In the MuJoCo window press 9  →  disable elastic band
```

Velocity commands: `w/s` forward/back, `a/d` left/right, `q/e` yaw, `Space` stop.

### 4.5 Sim-to-Real Deployment

Ensure the on-board Unitree controller is stopped, then:

```bash
cd ${UNITREE_RL_LAB}/deploy/robots/g1_29dof/build
./g1_ctrl --network eth0   # replace eth0 with your interface name
```

FSM transitions work via keyboard (`f` / `v` / `p`) or joystick (`LT + Up` /
`RB + X` / `LT + B`). The safety-value monitor logs observations and scores to
`log/safety_value/` for post-hoc analysis with `deploy/tools/safety_value_dashboard.py`
(live) or `deploy/tools/real_exp_offline_inference.py` (post-hoc).
